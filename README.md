# 动态辨识工场（Dynamic Identification Workshop）

一个本地运行的系统辨识小工场：用阶跃、伪随机二值序列（PRBS）、单脉冲等
输入激励被控对象，记录输出（含缺失与饱和标志），在“多个预处理 × 多个纯
延迟 × 多个模型阶次 × 多个模型族”的候选网格里辨识模型，并**以残差检验而
不是训练误差**来判断候选优劣。

技术栈：Go（标准库 `net/http` + `html/template`）、SQLite（`modernc.org/sqlite`，
纯 Go，无需 CGO）、gonum（最小二乘 / SVD / 特征值）、服务端生成 SVG。

## 安装与演示

```bash
go mod download
go test ./... -count=1
go run ./cmd/server --listen 127.0.0.1:5550
# 浏览器打开 http://127.0.0.1:5550 ，页首即“动态辨识工场”
```

首页点击“载入固定 fixture”即可得到内置数据集；进入数据集页划分估计/验证
段、选择预处理后点击“运行辨识并比较全部候选”。

## 数据口径（重要）

- **时间单位一律为秒。** 纯延迟按采样时间（秒）输入与展示，界面同时给出
  换算后的采样步数（`延迟步数 = round(延迟秒数 / 使用步长dt)`），避免
  “数组下标”歧义。
- **等间隔判定：** 估计窗口内相邻采样间隔的中位数为标称 `dt`，最大相对抖动
  超过 2% 即判为非等间隔。非等间隔数据**未显式勾选“重采样”时直接报错
  拒绝**，不会静默套用到离散等步（ARX/状态空间/一阶差分）模型。
- **显式重采样：** 勾选后按线性插值映射到等步网格（默认取原始中位数
  `dt`，可在表单指定）。运行页会标注“原始间隔 / 使用步长 / 最大抖动 /
  是否重采样”。
- **去均值 / 去趋势：** 均值或线性趋势**只在估计段的有效样本上估计**，
  再应用到全部数据；模型展示的预测/仿真会反变换回工程单位。
- **缺失处理：** `排除`（默认，掩码，不参与拟合与指标）、`线性插值`（按
  时间）、`置零`（需显式选择）。
- **饱和段：** 默认**只用于显示和诊断**（图上橙色竖条），不进入拟合；
  只有显式勾选“饱和段参与拟合”才纳入，且运行页公开被排除的样本数。
- **估计 / 验证划分：** 半开区间 `[t0, t1)`。两段重叠时仍会计算并存档
  （便于定位问题），但**禁止发布**，发布按钮在服务端按已保存配置再次
  拦截，不依赖前端状态。

## 模型与候选

每次运行枚举 `延迟候选(秒) × 阶次候选 × 模型族`：

- **ARX**：`A(q)y = B(q)u + c + e`，`na=nb=阶次`，含常数项，最小二乘。
- **状态空间**：`x'=Ax+Bu, y=Cx+c`，MOESP 子空间辨识 `(A,C)`，再按线性
  卷积基最小二乘估计 `B`、初态与截距；验证段**只重估初态，不重调参数**。
  一步预测在自由仿真之上叠加由估计残差拟合的 FIR 观测器。
- **受限一阶**：`y[k]=a·y[k-1]+b·u[k-d]+c`，强制稳定极点 `|a|<1`
  （极点附近细网格 + 条件最小二乘），增益自由；给出时间常数
  `τ=-dt/ln(a)` 与稳态增益 `b/(1-a)`。

候选排名顺序（训练误差仅展示、不参与第一名判定）：

1. 验证段残差白噪声（Ljung-Box Q 检验，p>0.05）；
2. 输入–残差交叉相关 CCF 越界数、残差自相关 ACF 越界数；
3. 验证段自由仿真 NRMS、一步预测 NRMS；
4. 前述并列时参数更少（低阶）者优先，并在页面同时展示各阶次的
   复杂度与残差检验结果。

页面展示：数据与一步预测拟合、验证段一步预测、自由仿真、估计/验证段的
残差 ACF 与输入–残差 CCF（红色柱表示超出 ±1.96/√N 的 95% 置信带）。

## 运行间对比

“运行对比”选择两条运行，并列给出：配置差异（分段、预处理、缺失策略、
饱和策略、延迟/阶次候选、dt）、样本差异（等间隔与否、抖动、缺失数、饱
和排除数、有效点数），以及两条最优候选的**参数差异**（延迟、增益、极点、
时间常数）与**残差差异**（ACF/CCF 越界、Ljung-Box p、仿真/预测 NRMS），
并给出按残差检验优先的结论。

## 发布阻断规则

- 估计段与验证段重叠 → 运行带“禁止发布”标记，发布被服务端拒绝；
- 无任何合格候选 → 拒绝发布；
- 已发布运行可撤销发布。

## 导出、清空与重新导入复核

- `GET /export` 导出单个 JSON 包（全部数据集 + 原始样本 + 全部运行报告，
  含发布状态与阻断原因），ID 保留。
- 首页可“清空数据库”，或在清空后“导入”导出包：导入必须勾选“先清空
  确认”；导入按原报告**原样恢复（不重算）**，可用原运行 ID 直接复核。
  需要重新计算时，在数据集页重新发起一次辨识即可。
- 单条运行可在运行页导出 JSON（NaN/Inf 通过可逆哨兵值编码）。

## 固定 fixture（验收数据）

`internal/fixture` 用固定种子确定性生成（LCG，跨机器字节一致）：

- 480 个样本，标称采样 1 s；真实一阶对象：**延迟 3 s、时间常数 8 s、
  稳态增益 2.0**；
- 输入：PRBS（保持 4–8 拍，±1）+ 第 100 拍的一个 +1 单脉冲 +
  第 330 拍起的 +1 阶跃；
- 第 150–230 拍为一段 ±35% 的采样时钟抖动（非等间隔）；
- 第 330–410 拍为输出饱和段（限幅 ±2.0）；
- 另有 3 个故意缺失的输出样本。

建议窗口：估计 `[20,140)`、验证 `[240,325)`；重叠窗口
`[20,140)` 与 `[120,200)` 用于触发发布阻断。

验收路径对应的自动化测试在：

- `internal/ident/ident_test.go`：真延迟/增益/时间常数恢复、错误延迟的
  残差相关性更强、重叠阻断、非等间隔拒绝与显式重采样、饱和默认排除、
  并列阶次必须残差也更白、延迟以秒表达；
- `internal/store/store_test.go`：持久化、导出→清空→导入后按原 ID 复核；
- `internal/web/web_test.go`：标题、fixture、端到端运行、SVG、发布阻断、
  非等间隔拒绝、延迟候选对比、导出/清空/导入。

